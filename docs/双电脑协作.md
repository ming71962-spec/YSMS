# 双电脑协作与首次启动

项目为用户确认的重要项目。现有本地 v0.2 是共同起点；GitHub 上传不等于网站发布。

## 另一台电脑首次启动

安装 Git、Node.js 24.x（含 npm）；安装固定版本 pnpm：

```powershell
npm install --global pnpm@11.25.0
```

Node.js 下载：https://nodejs.org/en/download
pnpm 兼容性与安装：https://pnpm.io/installation
Git 下载：https://git-scm.com/downloads

共同仓库：https://github.com/ming71962-spec/YSMS （公开，用户已确认）。执行 git clone https://github.com/ming71962-spec/YSMS.git，然后 cd YSMS。不需要复制 node_modules，也不依赖第一台电脑的 D 盘路径。

```powershell
node --version
pnpm --version
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm dev
```

访问终端显示的本机地址。第二台电脑须实际完成上述步骤才能称为双机验证完成。若暂时通过源代码 ZIP 转移，解压后可执行安装、测试、构建与开发命令，但该 ZIP 没有 Git 历史，正式协作仍应从 GitHub 克隆。

## 任务边界

| 范围 | 电脑 A | 电脑 B |
| --- | --- | --- |
| 第一批任务 | 水墨页面、彩色食材展示、手机布局 | 食材图文核对、素材补齐、来源与许可 |
| 文件 | App.tsx、FoodArt.tsx、style.css、ink.css、界面组件 | src/data、engine.ts、tests、public/art、数据脚本 |
| 后续 | 人数/用量界面、搜索筛选、关系图 | 有依据的用量换算、菜谱扩充与数据校验 |

types.ts、store.ts、依赖与锁文件由 A 统筹；B 需要修改时在任务/PR 中说明，确定字段示例后实施。不要因为分工限制而复制出另一套类型定义。

## 每项任务的流程

确保工作区没有未保存修改后：

```powershell
git switch main
git pull --ff-only origin main
git switch -c ui/mobile-layout
```

B 的任务可用 data/ingredient-images 等名称。各任务从最新 main 分出，不在两台电脑同时修改同一任务分支。不用日期目录复制源码作为长期协作方式。

完成后检查 git diff 和 git status，添加本任务文件并 commit、push，发起 PR。不要提交凭证、.env、个人路径、node_modules、dist 或本地备份。

合并前运行 pnpm test 和 pnpm build。GitHub Actions 已配置但必须推送后实际运行，当前不冒充线上检查已通过。main 保持可运行，由 A 统一整合和发布；不强制要求同账号自我审批。不要强推 main。

## 视觉与内容约定

页面水墨风；食材和菜品正常配色，优先复用有适用许可的现成素材。不能因为名字相近就拿鸡腿代替鸡翅中。原谱照片、主料示意、熟制参考明确区分，无准确图时保留名称。

复用 GitHub 内容需记录仓库、固定提交、源文件、许可和实际适用范围。Culinary Assets 的作者声明素材为 AI 生成后审阅，不能描述成手绘；保留第三方作者和许可。原有食材 ID 和浏览器存储键保持兼容。

## 备份、发布和个人数据

重要改动前按当前电脑的项目规则备份；GitHub 提交不能替代未跟踪文件的本地备份。第二台电脑若没有 backup-task.ps1，应先配置自己的备份工具，不硬编码第一台电脑路径。

浏览器里的收藏、已选食材和今日一桌不随 GitHub 同步。当前没有账号同步功能。

.openai/hosting.json 属于现有 Sites 站点配置，不含密钥，保留用于后续发布，不另建同名站点。GitHub 仓库与 Sites 源码存储分开管理，初期手动整合，未配置自动部署。

项目当前仅提供第三方许可说明；未擅自给用户自有代码指定开源许可，GitHub 仓库按用户确认保持公开，自有代码未指定开源许可。
