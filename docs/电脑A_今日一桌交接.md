# 电脑 A：今日一桌备餐面板

## 服务的任务

按产品定位，帮助用户选好下一顿饭后看清逐道缺料、整桌还需准备什么，并直接进入做法。份量按原谱，不计算人数与克重。

## 已实现

- 每道菜展示必需材料是否齐全及具体缺料；查看做法后可返回这一桌。
- 整桌必需材料按稳定 ID 去重，标明各道菜的用途；缺料可标记为“家里已有”，同步现有已选食材状态。
- 已有必需材料可折叠查看；原谱可选材料单独列出。某项材料在另一道菜中必需时，以必需项展示一次，同时保留可选用途。
- 页面与 TXT 导出共用一个汇总模型，包含逐道缺料、整桌缺料、已有项、可选项和原谱链接。
- 支持移除菜品、继续选菜、空菜单提示，保留水墨页面与彩色食物。

## 文件与协作边界

新增 MealPlanner.tsx、meal-planner.css，以及前端汇总投影 meal-plan.ts。App.tsx 接入面板；package.json 的 test 脚本增加 meal-plan.test.ts。

没有改 engine.ts、store.ts、types.ts、src/data、FoodArt.tsx 或图片映射，没有新增依赖。meal-plan.ts 复用既有 matchRecipe，只汇总 L1 必需和 L3 可选标注。当前数据没有 L2；B 若引入新的材料分级，双方需要先确定其采购含义并扩展投影与测试，不能静默当作必需或原谱可选。

B 后续可继续核对数据和图片。新菜谱仍以原稳定数据格式进入 catalog；共享类型、人数换算和单位转换需另行约定。GitHub 内容持续调研，本轮查看 Tandoor Recipes 的菜单/购物清单功能介绍：https://github.com/TandoorRecipes/recipes 。只参考功能流程，未复制其业务代码、数据或素材；继续复用已有 React、Lucide 等组件，不为小范围汇总引入整套服务。
